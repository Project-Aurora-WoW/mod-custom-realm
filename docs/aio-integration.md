# 📡 Интеграция AIO — Azeroth: Эхо Пустоты

> План внедрения [AIO](https://github.com/Zj92/mod-aio) (All-In-One) —
> фреймворка сервер→клиент UI для 3.3.5a (AzerothCore + Lua-движок).
> Референс реализации: [waloria](https://sourcecraft.dev/m-orlovrus59/waloria)
> (внутренний; AIO там используется для панели Adventure Panel).

---

## 1. Текущее состояние: AddonBridge

Наш UI-канал — аддон **AzerothEcho** + `AddonBridge.lua`:

| Аспект | Текущая реализация |
|--------|-------------------|
| Транспорт | `SendAddonMessage("AECHO", payload, "WHISPER", player)` |
| Payload | Текстовые строки `1:3:done;2:2:5` (прогресс), `AECHORIFTS:show`, `AECHOUI:tab:N` |
| Приём | `CHAT_MSG_ADDON` в аддоне, разбор строковой разметки |
| UI | Нативный Lua-аддон 3.3.5a: панель `/ae`, карта разломов, вкладки |

Сильные стороны: нет зависимостей, всё под нашим контролем.
Слабые: каждый новый UI-элемент = ручная разработка XML/Lua клиента,
строковый протокол разрастается.

## 2. Что даёт AIO

AIO позволяет **отправлять в клиент исполняемый Lua-код** (песочница),
сервер рисует UI напрямую: фреймы, кнопки, списки — без публикации
новых версий аддона.

| Возможность | Пример для реалма |
|-------------|-------------------|
| Серверные фреймы | Панель кампаний рисуется сервером — главы/награды из реестра без правки аддона |
| Динамические меню | Лор-архив Хрониста как полноценный UI (сейчас — gossip-строки) |
| Карты/пины | Разломы с живыми уровнями опасности из `AzerothEchoCampaigns` |
| Живые ивенты | Таймер Шторма Пустоты прямо в UI, без `/ae events` |

> **Рабочий пример AIO-системы**: [waloriaold/scripts/SpellAIO](https://sourcecraft.dev/m-orlovrus59/waloriaold)
> — сервер (`server.lua`) + клиент (`client.lua`) + SQL-таблицы +
> модульная логика (`spellclass.lua`). В notes.txt подтверждается
> транспорт: «Requires Rochet's AIO both client and server side».
> Полезно как образец организации серверного рендера UI в Фазе 2.

## 3. Сравнение подходов

| Критерий | AddonBridge (текущий) | AIO |
|----------|----------------------|-----|
| Зависимости | Нет | AIO-патч Lua-движка **или** клиентский AIO-аддон |
| Безопасность | Строки, риск минимален | Исполняемый код в клиенте — только наш сервер-отправитель |
| Разработка UI | Медленно (XML/Lua клиент) | Быстро (весь код на сервере) |
| Оффлайн-надёжность | Аддон работает всегда | Без AIO-части клиент игнорирует payload'ы |
| Проект Waloria | — | Развёрнутый AIO (Adventure Panel, XP-панель и др.) |

## 4. Фазы внедрения

### Фаза 0 — подготовка (без AIO)
- [ ] Аудит текущего AddonBridge: зафиксировать payload-схему в
      `lua_scripts/README.md` (уже описана) как контракт v1
- [ ] Убедиться, что аддон корректно деградирует без сервера
      (payload'ы неизвестных версий игнорируются)

### Фаза 1 — пилот (ко-существование)
- [ ] Установить AIO-совместимый Lua-движок (AIO-ветку поверх mod-ale)
      на **тестовый** реалм (не в production-набор `setup-build.sh`!)
- [ ] Один экран: «Живой статус ивентов» (Шторм/Кровавая Луна) через
      AIO-фрейм при входе и по команде `.aeevent status`
- [ ] AIO-код держать отдельным скриптом `40_AioPilot.lua` — не
      смешивать с основным контуром

### Фаза 2 — миграция UI (если пилот успешен)
- [ ] Панель кампаний (`/ae`) — серверный рендер из реестра
- [ ] Лор-архив Хрониста — gossip → AIO-меню
- [ ] AzerothEcho остаётся как fallback (прогресс на аддон-сообщениях)
- [ ] Дистрибуция AIO-аддона клиенту — через веб-каталог патчей
      (см. [`client-patch.md`](client-patch.md), Часть 4a)

### Фаза 3 — полная интеграция
- [ ] Секция `aio` в реестре `00_CampaignRegistry.ext` (флаги
      `enabled`, `version` — graceful degradation)
- [ ] Чек-листы в `testing-plan.md`
- [ ] Документация игроков

## 5. Риски

| Риск | Митигция |
|------|----------|
| AIO требует патченного Lua-движка | Клон `m-orlovrus59/mod-ale` — завести AIO-ветку после проверки лицензии/совместимости |
| Конфликт с нативным аддоном | Ко-существование: аддон рисует свою панель, AIO — только новые экраны до Фазы 2 |
| Исполняемый код в клиенте | Только payload'ы от доверенного сервера; AIO-канал игнорирует чужие сообщения |
| Обновления движка ломают AIO | Фиксация версии в `setup-build.sh` (ALE_URL уже параметризован) |
