# 🧪 План тестирования — Azeroth: Эхо Пустоты

> Чек-листы для ручного тестирования на тестовом реалме.
> Предполагает развёрнутый сервер (см. [`deployment.md`](deployment.md)).
> GM-команды выполняются в клиенте (аккаунт с gmlevel ≥ 3 в `acore_auth.account`).

---

## 0. Подготовка

```sql
-- Дать своему аккаунту GM-права
USE acore_auth;
UPDATE account SET gmlevel = 3 WHERE username = '<ваш_логин>';
```

В игре: `.tele stormwind` (или Оргриммар).

## 10. Outbox-награды и профильный скейлинг (wow-mod-delves паттерны)

> Референс: [wow-mod-delves](https://sourcecraft.dev/m-orlovrus59/wow-mod-delves)
> (DelveRewardDelivery — outbox/receipts; DelveScaling — профильные
> множители). Реализовано в echo-economy (outbox) и echo-pve (профиль ночи).
> Требует миграции `0015_token_outbox.sql` в **acore_characters**.

### 10.1 Outbox-доставка жетонов (echo-economy + echo-pve)

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 10.1.1 | Убить пустотного моба с дропом жетона (шанс 3%) | Сообщение «выпадает Жетон...»; в `realm_token_outbox` — строка с `reward_key=echo-pve:<guid>:<t>`, `delivered=0` |
| 10.1.2 | Перезайти тем же персонажем | Жетон доставлен (до BatchSize=5 за вход), `delivered=1`, квитанция в `realm_token_receipt` |
| 10.1.3 | Перезайти ещё раз | Повторной выдачи нет (квитанция уже есть — идемпотентность) |
| 10.1.4 | Рестарт worldserver между событием и доставкой | Награда доставляется после рестарта (durable intent) |
| 10.1.5 | Повторить SQL: `INSERT` с существующим reward_key | `INSERT IGNORE` не создаёт дубликат (уникальный ключ) |
| 10.1.6 | `EchoEconomy.Outbox.Enable = 0` + перезапуск | Дроп снова мгновенный? Нет — echo-pve пишет в outbox всегда; проверка: outbox строки копятся, доставка не идёт |
