# QA: Стартовое окно выбора кампаний и сопутствующие механики

Проверочный чеклист по брифу «Стартовое окно выбора кампаний, мониторинг
активности, интеграция аддонов, серверные механики, порядок запуска модулей».

---

## 1. Функциональные требования к интерфейсу (UI)

- [ ] При создании (первом входе) персонажа принудительно открывается окно выбора кампании.
- [ ] При каждом входе, пока `force_show_window=1` или `campaign_id IS NULL`, окно открывается снова.
- [ ] Окно двуязычно (ru/en) по локали клиента.
- [ ] В окне отображается график событий текущего модуля.
- [ ] Окно — центральное меню активностей проекта (вкладки Кампании/Ивенты/PvP/Карта).
- [ ] Есть команда повторного открытия: `/ae choose` | `/ae window` | `/ae select` (клиент),
      серверный аналог `.ae campaign`.

## 2. Техническая реализация (Сервер / БД / Клиент)

- [ ] Таблица `realm_campaign_profile` (миграция `0042`) создана в `acore_characters`.
- [ ] При входе `40_CampaignWindow.lua` читает профиль: строка отсутствует -> показать окно.
- [ ] Сервер блокирует управление (`SetPlayerLock(true)`) при показе окна.
- [ ] Сервер шлёт клиенту `AECHOUI campaign:show` при необходимости показа.
- [ ] Клиент ловит `AECHOUI` -> `ShowCampaignSelector()`.
- [ ] ESC блокируется, окно нельзя закрыть без выбора.
- [ ] Клики по миру блокируются (невидимый модальный блок).
- [ ] После выбора клиент шлёт `AECHOSEL campaign:<id>` серверу.
- [ ] Сервер принимает выбор (ADDON_EVENT_ON_MESSAGE), сбрасывает флаг, пишет `campaign_id`, снимает блокировку.
- [ ] Персонаж остаётся на месте (движение заблокировано) до подтверждения.

## 3. Аддоны и иммерсивность

- [ ] `CampaignWindow.lua` в аддоне AzerothEcho зарегистрирован в `.toc`.
- [ ] Таймеры событий визуализируются в окне выбора (график).
- [ ] Скрытые статусы персонажа (флаг, выбранная кампания) отображаются.
- [ ] Окно стилизовано под арт-стиль проекта (фиолет/голубь Эха).

## 4. Проверка серверных механик

- [ ] Расчёт урона/аур/триггеров не сломан (регресс после фиксов audit) — прогон стандартных боевых механик.
- [ ] Передача данных сервер<->клиент (AECHO/AECHOEV/AECHOSEL) корректна.
- [ ] Клиентские визуалы соответствуют расчётам сервера (без desync).
- [ ] Поведение при потере пакета/высоком пинге: игрок остаётся заблокированным до ответа;
      повторный выбор не начисляет дважды (идемпотентность — `ON DUPLICATE KEY UPDATE`).

## 5. Порядок запуска модулей и Lua-скриптов

- [ ] Ядро собирается с модулями (`echo-*`, `mod-ale`, внешние).
- [ ] `mod-ale` грузится до Lua-скриптов (порядок по алфавиту каталогов).
- [ ] `.ext` реестры (`00_CampaignRegistry`, `00_LoreRegistry`) грузятся первыми.
- [ ] `40_CampaignWindow.lua` читает реестр и таблицу БД — зависимости выполнены.
- [ ] Lua-скрипты не конфликтуют по хукам (проверено audit).
- [ ] Правило no-duplicate: `40_CampaignWindow` не дублирует хендлеры 3/6/7/18 уже занятые другими.

## 6. QA / наблюдение за игроком

- [ ] Playtest: выдача NPC -> диалог -> механика -> дроп -> награда (по всем 4 кампаниям).
- [ ] Локализация: все тексты (интерфейс, лор, аддоны) на ru/en корректны.
