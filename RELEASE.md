## Блокеры релиза — требуют ручной работы вне репозитория

1. **`patch-x.mpq` не собран.** В репозитории нет исходников для него: нужны базовый
   `Patch-T.MPQ.rar` (waloriaold), DBC титула 48 и маунта 70010, BLP магазина и
   клиентский аддон AIO_Client (Rochet2/AIO). Инструкция — `docs/client-patch.md` ч. 1–4, 7–8.
   **Пока файла нет, в манифесте он помечен `required: false`** — лаунчер не будет
   ломать клиент 404-й. После сборки: выложить, пересчитать sha256/size, поставить `required: true`.
2. **Тестовый прогон на живом сервере.** Нужны MySQL, собранное ядро (`bin/` в клоне
   `azerothcore-wotlk` содержит только лаунчеры — сборки нет) и клиент 3.3.5a:
   миграции 0001–0022, чек-листы `docs/testing-plan.md` (разделы 1, 11–15).
   Координаты спавнов Зул'Драка и Драконьего Погоста — приблизительные, выверка нужна на клиенте.
3. **Проверка на клиенте:** титул 48, маунт «Бездна-Пегас», карта 5000 (`patch-Z`),
   отображение displayid НПС (0008), AIO-магазин (рукопожатие, доставка кода).

## Известные дефекты, найденные аудитом и не исправленные (нужен MySQL)

| Файл | Проблема | Влияние |
|------|----------|---------|
| `0004_campaign_reward_item.sql` | INSERT item 70001: 84 колонки / 117 значений; значения сдвинуты (описание попадает в `VerifiedBuild`) | Миграция падает → нет «Слезы Рассвета» (70001), скрипт `Campaign1.lua` не может выдать награду |
| `0005`, `0009`, `0012` (items) | Вставки на 77 значений при 78 колонках — лишний `0` перед строкой описания | Падают → нет наград кампаний 2/4 и валюты «Жетон Эха» (70005) |
| `0018_eluna_scripts_tier_a.sql` | item 70008: запятая внутри строки описания («…при тебе, тем громче…»), `Stackable`/`maxcount` сдвинуты | Падает → нет «Осколка Пустоты» |
| `0005`, `0010` (creature_template) | Набор колонок не совпадает с фактической схемой AC (`soundoverridesubclass`, `minhealth`, `family`, `trainer_*` отсутствуют; `rank`/`npcflag` в другом порядке; 38–39 значений на 38 колонок) | Падает на AC → шаблоны НПС не создаются |
| `0021_public_scripts.sql` | Часть `acore_world` по схеме WotLK (`modelid1`, `dmgschool`, `spawndist`, `creature.id`) | Падает; рабочий НПС создаёт `0022` |
| `0009`, `0013`, `0014`, `0015`, `0017`, `0018`, `0021` | Файлы пишут и в `acore_characters` (через `USE` или по инструкции) — `0002` тоже | Требует ручного применения в каждую БД; безопасно только по разделу «Порядок применения» в `sql/README.md` |

⚠️ Эти шесть пунктов — одна и та же причина: item/creature схема писалась по памяти,
а не по `sql/base`. Правка требует сверки с живой БД (`DESCRIBE item_template`,
`DESCRIBE creature_template` после инициализации core). Без MySQL сделать это вслепую —
значит заменить одну ошибку на другую, поэтому здесь честно зафиксировано.

## Порядок выкладки

1. Применить миграции 0001–0022 по `sql/README.md` → «Порядок применения»
   (`0022` обязателен после `0021`).
2. `.reload creature_template`, `.reload items` в консоли worldserver.
3. Скопировать `lua_scripts/` (включая `extensions/`, `Dep_*`, `lualzw-zeros`) в каталог Lua сервера.
4. Собрать ядро с модулями `modules/echo-*` (`scripts/setup-build.sh`, `modules/README.md`).
5. Выложить `client/` (manifest.json, patch-Z.mpq, addons/AzerothEcho.zip) на статический хостинг.
6. Собрать и выложить `patch-x.mpq` (клиентский патч) — снять `required: false`.
7. Прогнать `docs/testing-plan.md`; после — онбординг (сайт/дискорд, реалм-лист).
